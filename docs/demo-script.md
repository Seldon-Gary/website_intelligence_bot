# Сценарий демонстрации

Требования сдачи — показать работу **MCP-сервера, API и Telegram-бота**. Ниже порядок, в котором это снимается за один заход на 3–5 минут.

## Перед записью

- [ ] `.env` заполнен, но **не попадает в кадр** (там токены)
- [ ] Один конкурент уже добавлен и **просканирован** — чтобы `/diff` было с чем сравнивать
- [ ] Оба терминала открыты и видны: `run_api.ps1`, `run_bot.ps1`
- [ ] Выбран сайт, который точно открывается (проверь заранее — чужой сайт может лечь именно во время записи)

## Кадр 1. MCP-сервер сам по себе

```powershell
.\venv\Scripts\python.exe -m scripts.check_mcp https://example.com
```

Что проговорить: это отдельный процесс, запускается по stdio, отдаёт **24 инструмента**, умеет водить браузер. Бота и API здесь нет вообще — сервер самостоятельная сущность.

Показать в выводе: список инструментов, содержимое открытой страницы, путь сохранённого скриншота.

## Кадр 2. API

Открыть <http://127.0.0.1:8000/docs>.

- `POST /competitors` — добавить конкурента прямо из Swagger
- `GET /compare` — сводка

Проговорить, зачем слой вообще нужен: обход идёт минуты, поэтому бот кладёт задачу в очередь и сразу отвечает, а результат приходит потом.

## Кадр 3. Бот — главное

```
/add https://<сайт> Название
/list
/scan 1
```

Ответ приходит сразу — «принял в работу». **Не вырезай эту паузу полностью**: она и есть суть. Пока идёт обход — переключись на терминал API.

## Кадр 4. Логи во время обхода

В терминале `run_api.ps1` видно:

```
Скан 1: инструменты агента — browser_navigate, browser_snapshot, ...
Скан 1: обход закончен, вызовов инструментов 11, переходов 3
Оффер собран: 3 тарифов, 5 выгод
```

Это ключевой момент всей демонстрации: **11 вызовов браузера — это 11 решений модели**, а не наши `if`. Мы не писали, по каким ссылкам идти.

## Кадр 5. Результат в чате

Скриншот сайта + разобранная карточка: заголовок, выгоды, тарифы с ценами, кнопки. Внизу — сколько страниц и вызовов браузера.

## Что сказать в конце

Один тезис, ради которого всё и делалось:

> Здесь MCP взят не для галочки. Playwright MCP держит **живой браузер между вызовами** — модель открывает страницу, читает её, сама находит ссылку на тарифы и переходит по ней в той же сессии. Обычный парсер знает селекторы и ломается на новом сайте; здесь добавление конкурента — это команда `/add`, а не работа программиста.

Второй тезис, если останется время:

> Агент читает чужие сайты, где может быть написано что угодно, в том числе адресованное ему. Поэтому у него нет доступа к базе — только браузер, и только 6 инструментов из 24: читать и переходить можно, заполнять формы и выполнять код на странице — нет.
